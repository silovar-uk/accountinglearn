# 基礎簿記コース実装仕様

## 目的

基礎簿記を資格試験の章立てだけで並べず、経営ケースで必要になった論点へ戻れる形で提供する。

初期コースはCASE 1「黒字なのに、口座にお金がない」の理解に必要な内容へ限定する。

## 初期6単元

1. 売上と入金
2. 売掛金
3. 前受金
4. 費用と支払い
5. キャッシュフロー
6. 運転資本

各単元は約8〜9分、4問で構成する。全体は24問、想定50分。

## 学習フロー

各単元を次の順で進める。

1. 経営上なぜ必要かを確認
2. 3つの概念カードを読む
3. 取引場面・仕訳・数値問題へ回答
4. 回答直後にヒントまたは解説を確認
5. 単元の要点を振り返る
6. 対応するCASE 1のページへ移動する

一つの画面では一つの説明または一つの問題だけを扱う。

## 問題形式

初期版では次の3形式に限定する。

- `singleChoice`
- `multipleChoice`
- `numberInput`

新しい問題形式を加える場合は、教材JSON、採点エンジン、バリデーター、単体テスト、ブラウザテストを同じPRで更新する。

## 保存データ

基礎コースの保存領域は既存のケース回答と分離する。

```text
state.basicsProgress
state.basicsMistakes
state.basicsCourse
state.skillProgress
```

`basicsProgress`には回答、確認時刻、得点、回答履歴、単元完了時刻、最高得点、最後に開いたスライドを保存する。

既存のJSON書き出し・読込はstate全体を保存するため、基礎コースのデータも追加処理なしでバックアップ対象になる。

## 技能習得

単元完了時の得点率を技能習得度へ変換する。

- 80％以上：100、習得
- 60〜79％：75、要復習
- 1〜59％：50、練習中
- 未回答：0

一度記録した最高習得度は、後の再挑戦で下げない。

初期コースで追加した技能は次の3つ。

- `accounting.advance-receipts`
- `accounting.expense-payment-timing`
- `analysis.working-capital`

## 復習

誤答は`basicsMistakes`へ追加する。同じ問題へ再回答して正解した場合は復習候補から除外する。

既存の復習画面には、ケース問題と基礎問題を別セクションで表示する。

## CASE 1との接続

各単元の`caseLinks`はケースIDとページIDを持つ。表示側でページ番号を決め打ちせず、現在のケースJSONからページIDを検索する。

これにより、ページ順序が変わってもIDが維持される限りリンクを保てる。

## 教材データの検証

`scripts/validate-basics.mjs`で次を確認する。

- コース・単元・問題・選択肢ID
- 単元順序
- 想定時間の合計
- 技能IDの存在
- 推奨前提単元が前方にあること
- 概念・要点の不足
- 問題数
- 問題形式
- 正解選択肢
- 数値問題の期待値と単位
- CASE 1リンク先の存在

## 品質確認

高速検証：

```bash
npm run check
```

実ブラウザ検証：

```bash
npm run test:e2e
```

Playwrightでは、PCとPixel 7相当の両方で最初の単元を完了し、回答保存、100％得点、技能習得、再読込後の完了表示を確認する。
