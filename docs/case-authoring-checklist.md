# ケース制作チェックリスト

## 企画

- [ ] ケースで扱う経営上の問いが一文で説明できる
- [ ] 学習目標が行動として記述されている
- [ ] 前提技能と練習技能を区別した
- [ ] 想定時間と設問量が釣り合っている
- [ ] 架空情報と公開情報を区別した

## 物語

- [ ] 主人公の役割と依頼内容が最初のページで分かる
- [ ] 数字を確認する理由が物語上にある
- [ ] 読むだけの情報と判断に必要な情報を分けた
- [ ] 結末が模範解答の読み上げだけになっていない

## 財務資料

- [ ] 単位と期間が明記されている
- [ ] PL、BS、CFの数値が整合している
- [ ] 合計、増減、期首期末が再計算できる
- [ ] 設問で使わない資料をむやみに増やしていない
- [ ] 数値の根拠を教材内で説明できる

## 設問

- [ ] 問いが一度に複数の判断を要求していない
- [ ] 選択肢の粒度がそろっている
- [ ] 誤答理由が説明できる
- [ ] 正答を知らなくても資料から考えられる
- [ ] 各設問に技能IDが付いている
- [ ] 自動採点と自己評価を適切に使い分けた

## ヒント

- [ ] level 1で正答を明示していない
- [ ] level 2で見る資料や考え方を示している
- [ ] 必要な場合だけlevel 3で式や手順を示す
- [ ] ヒントと解説の役割が重複していない

## 提案・自由記述

- [ ] 事実、原因、施策が分けられている
- [ ] 短期対応と再発防止を区別している
- [ ] 複数の妥当な回答を許容している
- [ ] 文字列一致による自動採点をしていない
- [ ] 自己評価の観点が具体的である

## 保存互換

- [ ] 公開済みcase idを変更していない
- [ ] 公開済みpage idを変更していない
- [ ] 公開済みstep idを変更していない
- [ ] 選択肢IDと資料IDの変更影響を確認した
- [ ] contentVersionを更新した

## 公開前

- [ ] `npm run check`が成功する
- [ ] PCのブラウザ回帰が成功する
- [ ] スマホのブラウザ回帰が成功する
- [ ] オフライン再表示が成功する
- [ ] 誤字・日本語・会計内容を人間が確認した
- [ ] draft → reviewing → tested → publishedの順で状態を更新した
